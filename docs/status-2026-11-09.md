# 2026-11-09 原生热键与显示恢复

## 原生热键

本机已移除 Air14 Hotkeys App、登录配置、旧应用备份、设置、日志、构建产物和本地 App 源码。删除前 App 没有运行；此前亮度操作不依赖该进程。仓库仅保留 EFI 热键的自定义 SSDT 源码与配置片段，不发布后台助手。

`SSDT-BKEY` 将 Darwin 下的 EC 亮度事件转发给 VoodooPS2，并通过 RMCF 配置 Insert → Help/Insert、Print Screen → F13。其他系统继续调用重命名后的原始 EC 方法。用户报告首次映射的亮度加减方向相反，现已交换为 `_Q8E → 0x0406`、`_Q8F → 0x0405`；新 AML 已写入 EFI，方向修正尚待下次启动实测。

SSDT 编译零错误、零警告；DSDT 重命名各匹配一个原始方法；完整配置通过 ocvalidate。方向修正只改变 SSDT 中两个通知字节，其他 EFI 文件逐项校验一致。离线校验不代表全部物理热键已通过测试。

麦克风静音、Wi-Fi、显示切换、Fn+R、Fn+Q、Fn+Space 及 FnLock 全部组合尚未完成原生适配验证。移除 App 后不再提供其菜单栏、软件 FnLock 开关或额外快捷操作；不宣称本机所有热键均可用。安装方法见 [原生热键](setup.md#原生热键)。

## 显示与重启

显卡源码包含三处显示路径归属修正：没有当前显示路径的 watermark setup、watermark update 和 DBUF 分配回调不再污染其他活动显示的资源状态；属于有效路径的真实资源错误仍保留失败保护。相关源码通过 217 项 CPU/mock 检查，并完成 Debug / Release 构建。

本机已组合使用该驱动与 OpenCore `UEFI → Output → ReconnectGraphicsOnConnect = true`。用户确认该候选有一次正常重启成功；后续失败发生在一次性保护程序恢复旧配置之后。现已正式保留候选并停用自动回退，保留手动恢复备份。连续重启、正常关机及短按电源键恢复仍待验证，不能将一次成功写成问题完全解决。

内屏 120Hz、HDMI 144Hz 与 HiDPI 的既有配置保留。热键方向修正没有修改显示驱动、蓝牙或重启配置；本轮没有重启系统。蓝牙仍使用 IntelBluetoothFirmware / IntelBTPatcher 2.5.3，服务与耳机播放的稳定性边界见 [已有记录](status-2026-11-07.md#蓝牙)。
