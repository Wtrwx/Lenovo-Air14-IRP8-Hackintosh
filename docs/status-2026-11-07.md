# 2026-11-07 蓝牙与热键状态

这是当前进展记录，不是修复完成声明。验证对象为 README 中的 Air14 IRP8 与 macOS 26.7.2（25G332）。本次更新仅发布状态及脱敏结果，不发布完整 EFI、系统二进制、设备身份、配对数据或原始日志。

## 蓝牙

- 已部署 IntelBluetoothFirmware 2.5.3 与 IntelBTPatcher 2.5.3；部署时核对了实际 EFI 中的文件，未开启 HDMI 试验配置。
- 已观察到控制器开启、AirPods 状态广播和系统设置发起扫描。已有采集中的配对状态事件与设置设备发现事件均为零，因此这些广播不能证明配对和音频播放成功。
- 用户反馈：蓝牙有时正常，但耳机没有声音。尚未完成默认输出设备、播放路由、A2DP / HFP、断连与重连的对照验证，不能直接归因于其中某一环节。
- 较早一轮检查中，launchd 报告 bluetoothd 连续崩溃 16 次、最近一次终止信号为 SIGBUS，并延迟重试；表现为蓝牙设置或设备卡住。
- 当日 15:13 左右的崩溃报告记录 `KERN_MEMORY_ERROR`，地址落在 bluetoothd 的 `__TEXT` 段，并包含 APFS 压缩数据哈希不匹配、压缩 inode 分页读取失败。该证据支持系统文件读取 / 完整性故障参与崩溃，尚不能认定为 SSD 硬件损坏，也不能据此解释所有历史蓝牙问题。
- 本地只读校验中，bluetoothd 的 x86_64 CodeDirectory 共检查 2885 个代码页，其中 4 页哈希不一致；同期 BlueTool 的 76 页、bluetoothuserd 的 152 页未发现不一致。完整 Apple 签名校验也报告 bluetoothd 内容或签名被修改。代码页校验本身不验证 Apple 证书信任。
- 系统于 16:13 重新启动。17:01 检查时 bluetoothd 正在运行，但签名校验仍失败。上述“16 次崩溃”属于此前检查，不能写成当前启动已崩溃 16 次。

尚未替换系统文件、修改系统快照或执行磁盘修复。下一步先核对磁盘 / 系统文件完整性及可用的同版本恢复来源，再分别验证服务稳定性与耳机播放链路。修复后需重新检查签名、连续运行、扫描配对、实际播放和重连，才能更新为稳定可用。

## 热键

- 当前本机运行的后台助手为 Air14 Hotkeys 1.2.0，保持 `local.air14.Hotkeys` 身份。已有登录服务后台启动、辅助功能授权和自动启用的记录；尚未完成重新登录后的持久性验证。
- 已有音量及亮度操作成功返回的现场记录；这不代表内置声卡、内置麦克风或全部物理组合键适配完成。
- 现有生产回调检查通过 87 项，检查不发送系统按键、不执行硬件写入。这些检查没有覆盖正确的 FnLock 语义，不能作为 FnLock 正确性的证明。
- 已确认当前助手未区分普通 F 键与功能操作。用户要求的语义为：FnLock 锁定时输出普通 F1–F12，未锁定时执行音量、亮度等功能。修正尚未实施。
- 当前主界面以诊断记录为主，精简主界面与单独诊断入口的改版尚未实施。
- 固件桥接在此前运行检查中未加载。Fn+Q 性能写入未完成；Fn+Space 背光行为未完成确认；Fn+R 检查没有发现可用的同分辨率 60 / 120Hz 成对模式，因此不会强制切换。F7 依赖可用外屏，F8 物理按键仍待验证。
